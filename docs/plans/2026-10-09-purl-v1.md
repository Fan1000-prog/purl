**Goal:** Turn VendastaTalk v0.8.0 into Purl v1.0.0 — a free, MIT, local-first dictation app for macOS and Windows with Parakeet speech-to-text, optional local-LLM cleanup, a Purl-branded UI, a README with benchmark + case study, and a separate landing page.

**Architecture:** Tauri v2. Rust core in `app/src-tauri/src` split into `engine/` (models, in-process Parakeet via `transcribe-rs`, `llama-server` sidecar), `platform/` (OS seams: injector, focus reader, locator), and the platform-blind pipeline (cleanup, transforms, commands, snippets, corrections). ## Global Constraints

- Product name `Purl`; bundle identifier `app.purl.desktop`; Rust crate `purl` (lib `purl_lib`); tagline "Speak softly. Send it clean."
- Licence MIT, copyright line `Copyright (c) 2026 Fani Bango`. No AI attribution anywhere (commits, PRs, docs, code comments).
- No network at dictation time. Network only for: model downloads (huggingface.co, github.com), update check (github.com). Any new host is a spec change.
- Sidecars bind `127.0.0.1` only, random free port.
- No BYOK, no Ollama, no whisper.cpp, no Homebrew in the shipped app. (whisper.cpp is allowed **only** inside `bench/` for the comparison.)
- STT model: `parakeet-tdt-0.6b-v3` int8 ONNX from `istupakov/parakeet-tdt-0.6b-v3-onnx`. LLM default: `Qwen_Qwen3.5-2B-Q4_K_M.gguf` from `bartowski/Qwen_Qwen3.5-2B-GGUF`; optional 4B.
- Every registry model has a pinned sha256 (values in Task 4).
- **Design (amended 2026-10-10):** the `~/Desktop/Purl-Design/02-motion` pack + `01-logo-locked` logo (see spec "Redesign"). No mascot. Instrument Serif + Geist + Geist Mono, OFL, bundled. Patterns may echo wisprflow.ai / Heidi Dictate; their text, logos and assets never.
- macOS: **Apple Silicon only** (`aarch64`) DMG — no Intel build in v1 (amended 2026-10-10, see spec Non-goals), signed with a **stable self-signed identity** "Purl Self-Signed" so the Accessibility grant survives updates (ad-hoc signing changes the code hash every build and macOS would drop the grant). 
- Windows: x64 NSIS per-user installer, unsigned in v1. ONNX Runtime = Microsoft's official `onnxruntime-win-x64-1.28.0` (CPU-only, sha256-pinned), linked dynamically via `ORT_LIB_LOCATION` + `ORT_PREFER_DYNAMIC_LINK=1`, `onnxruntime.dll` bundled beside `purl.exe`.
- Personal dictionary ships with one entry: `Purl`.
- Copy: Google Chat, never Slack, in any example text.
- Clippy `-D warnings` and `cargo fmt --check` are CI gates.

5. **Hotkey pressed twice fast / during processing.** Expect: one session, second press ignored with no crash. Test: Task 3 `second_session_rejected_while_processing` (pipeline guard extracted to a testable fn).

### Shared contract — Tauri commands and events (Tasks 4, 5, 6, 9, 10 all rely on this)

```ts
// app/src/types.ts  (added in Task 4; UI tasks import from here)
export type ModelKind = "stt" | "llm";
export type ModelState = "missing" | "downloading" | "ready" | "failed";
export interface ModelView {
  id: string;            // "parakeet-v3" | "qwen3.5-2b" | "qwen3.5-4b"
  label: string;         // "Parakeet v3 (speech)"
  kind: ModelKind;
  size_bytes: number;
  state: ModelState;
  downloaded_bytes: number;
  error: string | null;  // user-facing sentence when state === "failed"
}
export type EngineState =
  | { state: "missing" } | { state: "loading" } | { state: "ready" }
  | { state: "idle" }    | { state: "failed"; reason: string };
export interface EngineStatusView { stt: EngineState; llm: EngineState; }
export type CleanupMode = "off" | "fast" | "smart";
export type Trust = "granted" | "denied" | "not_required";
```

Commands: `models_status(): ModelView[]`, `download_model(id: string): void` (returns immediately), `cancel_download(id: string): void`, `delete_model(id: string): void`, `engine_status(): EngineStatusView`.
Events: `model-progress` `{ id, downloaded_bytes, size_bytes }` (≤4/s per model), `model-done` `{ id, ok: boolean, error: string | null, kind: "disk_full"|"offline"|"http"|"checksum"|"cancelled"|"io"|"stopped"|null }` (a cancel still sends `ok:false, kind:"cancelled"`, but it is not recorded as a failure: the model then reports `state:"missing"` with its partial `downloaded_bytes` and `error: null`), `engine-status` `EngineStatusView` (on every change), existing `state` events (`idle|recording|processing|done|error`) unchanged.
